# 功能规范: 企业级 CRM 系统

**功能分支**: `001-enterprise-crm`
**创建时间**: 2026-01-18
**状态**: 草稿
**输入**: 用户描述: "构建企业级 CRM 系统，参照 CordysCRM 开源项目，实现 L2C 业务闭环，按模块优先级分阶段实现"

## 项目概述

本项目旨在构建一套企业级客户关系管理系统（CRM），实现从线索到现金（L2C: Leads to Cash）的完整业务闭环。系统将支持线索获取与分配、客户与联系人管理、商机跟进、合同签约及回款执行等核心销售流程，并在此基础上逐步集成 AI 智能辅助能力。

## 模块优先级规划

| 优先级 | 模块分类 | 包含模块 | 说明 |
|--------|----------|----------|------|
| P0 | 系统基础 | 用户权限、组织架构 | 系统运行的基础设施 |
| P0 | L2C 核心 | 线索、客户、联系人、商机、产品、合同、回款 | 核心业务闭环 |
| P1 | 业务增强 | 跟进记录、数据分析、仪表盘 | 提升销售效率 |
| P2 | AI 智能 | MCP 集成、智能创建、智能查重 | AI 辅助能力 |
| P3 | 第三方集成 | 企业微信、钉钉、飞书 | 办公协作集成 |

## 用户场景与测试 *(必填)*

### 用户故事 1 - 系统基础设施搭建 (优先级: P0)

作为系统管理员，我需要能够管理企业的组织架构、用户账号和角色权限，以便控制不同人员对系统功能和数据的访问权限。

**优先级原因**: 这是整个系统运行的基础，没有用户和权限管理，其他所有业务功能都无法正常使用。

**独立测试**: 可以通过创建组织架构、添加用户、分配角色并验证权限控制来完全测试，交付基础的系统访问能力。

**验收场景**:

1. **给定** 系统刚部署完成，**当** 管理员首次登录时，**那么** 系统提示设置初始管理员密码并进入系统
2. **给定** 管理员已登录，**当** 创建新的组织部门时，**那么** 部门出现在组织架构树中
3. **给定** 已有组织架构，**当** 管理员创建新用户并分配到某部门时，**那么** 用户可以使用分配的账号登录
4. **给定** 系统中有多个角色，**当** 管理员为用户分配特定角色时，**那么** 用户只能访问该角色授权的功能和数据

### 用户故事 2 - 线索管理 (优先级: P0)

作为销售人员，我需要能够录入和管理潜在客户线索，跟踪线索状态，以便将有价值的线索转化为正式客户。

**优先级原因**: 线索是销售漏斗的入口，是 L2C 流程的起点，没有线索管理就无法启动销售流程。

**独立测试**: 可以通过创建线索、更新线索状态、转化线索为客户来完全测试，交付线索全生命周期管理能力。

**验收场景**:

1. **给定** 销售人员已登录系统，**当** 录入新线索信息时，**那么** 线索保存成功并显示在线索列表中
2. **给定** 已有线索记录，**当** 销售人员更新线索状态（如：初步接触→有意向→转化）时，**那么** 状态变更被记录并可追溯
3. **给定** 一条高意向线索，**当** 销售人员选择"转化为客户"时，**那么** 系统自动创建客户记录并关联原线索
4. **给定** 大量线索数据，**当** 销售人员按条件筛选或搜索时，**那么** 系统快速返回匹配的线索列表

**验收场景**:

2. **给定** 已有客户记录，**当** 为客户添加联系人时，**那么** 联系人与客户正确关联
3. **给定** 一个客户有多个联系人，**当** 查看客户详情时，**那么** 可以看到所有关联的联系人列表

### 边界情况

- 当用户尝试删除有关联数据的记录时，系统应提示无法删除并说明关联关系
- 当多个用户同时编辑同一记录时，系统应提供冲突提示或自动合并机制
- 当数据导入包含重复记录时，系统应提供查重确认流程
- 当用户权限不足时，系统应友好提示并引导申请权限
- 当网络中断时，系统应保存用户未提交的数据草稿

### 关键实体

- **用户 (User)**: 系统使用者，具有账号、密码、所属部门、角色等属性
- **角色 (Role)**: 权限集合，定义用户可访问的功能和数据范围
- **部门 (Department)**: 组织架构单元，支持多级层次结构
- **线索 (Lead)**: 潜在销售机会的初始形态，包含来源、联系方式、状态等
- **客户 (Customer)**: 正式的业务往来对象，包含企业信息、行业、规模等
- **联系人 (Contact)**: 客户企业中的具体联系人，包含姓名、职位、联系方式等
- **商机 (Opportunity)**: 具体的销售机会，包含预计金额、阶段、预计成交日期等
- **产品 (Product)**: 公司提供的产品或服务，包含名称、价格、单位等
- **合同 (Contract)**: 正式的销售协议，包含金额、期限、状态等
- **回款 (Payment)**: 合同的资金回收记录，包含计划金额、实际金额、日期等
- **跟进记录 (Activity)**: 与客户的互动记录，包含类型、内容、时间等

## 假设与依赖

### 假设

1. 用户具备基本的计算机操作能力
2. 企业已有明确的销售流程和阶段定义
3. 产品/服务目录相对稳定，不需要频繁大规模变更
4. 初期用户规模在 100 人以内
5. 数据保留期限遵循行业标准（至少 3 年）

### 依赖

1. 项目章程中定义的技术栈（Java 8, Spring Boot 2.7.x, Vue 3, MySQL 5.7）
2. 企业已有的用户身份认证体系（如需对接）
3. 第三方平台的开放 API（企业微信、钉钉、飞书）
4. AI 能力需要 OpenAI API 或兼容接口的可用性
