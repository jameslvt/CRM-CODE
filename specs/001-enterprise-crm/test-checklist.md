# 企业级 CRM 系统测试清单

基于 `specs/001-enterprise-crm` 下的 `spec.md` 和 `data-model.md` 生成。

## 1. 系统基础 (System Basics) [P0]

### 1.1 用户与认证 (User & Auth)
- [ ] **登录**: 验证管理员及普通用户能否使用账号密码登录。
- [ ] **多租户/隔离**: 验证不同部门用户登录后的数据隔离（若适用）。
- [ ] **账号管理**:
    - [ ] 创建新用户（填写必填项：用户名、密码、部门、角色）。
    - [ ] 验证用户名唯一性。
    - [ ] 禁用用户账号，验证其无法登录。

### 1.2 角色与权限 (RBAC)
- [ ] **角色管理**: 创建新角色并分配权限（菜单/按钮）。
- [ ] **权限验证**:
    - [ ] 验证无权限用户无法看到对应菜单或按钮。
    - [ ] 验证 API 级别的权限拦截（直接调用接口是否被拒绝）。
- [ ] **数据权限**: 验证“本人”、“本部门”、“全部”数据权限的数据可见性差异。

### 1.3 部门管理 (Department)
- [ ] **组织架构**: 创建、修改部门，验证层级结构显示正确。


## 2. L2C 核心业务 (L2C Core) [P0]

### 2.1 线索管理 (Leads)
- [ ] **创建线索**:
    - [ ] 录入必填项（名称等），验证数据保存成功。
    - [ ] 验证手机号/邮箱格式校验。
- [ ] **状态流转**: 验证状态变更（新建 -> 跟进中 -> 已转化/已关闭）。
- [ ] **线索转化**:
    - [ ] 执行“转化为客户”操作。
    - [ ] 验证是否自动生成了客户记录、联系人记录。
    - [ ] 验证原线索状态是否更新为“已转化”。
- [ ] **线索分配**: 验证管理员能否将线索分配给其他销售，验证负责人（Owner）字段更新，原负责人不可见（非公开时）。
- [ ] **校验规则**:
    - [ ] 尝试录入重复手机号，验证系统拦截。
    - [ ] 验证必填项缺失时的提示信息。
- [ ] **导入导出**:
    - [ ] 下载线索导入模板。
    - [ ] 批量导入 Excel 线索数据，验证数据格式错误处理（如日期格式不对）。
    - [ ] 批量导出线索数据，验证与列表数据一致。

### 2.2 客户管理 (Customers)
- [ ] **客户信息**:
    - [ ] 创建客户，验证名称必填。
    - [ ] **查重机制**: 尝试创建同名客户，验证是否提示重复。
    - [ ] 验证字段长度限制（如名称不能超过200字符）。
- [ ] **360度视图**:
    - [ ] 进入客户详情页，验证是否能看到关联的联系人、商机、合同、回款、跟进记录。
    - [ ] 验证点击关联数据能正确跳转或展示详情。
- [ ] **公海池逻辑**:
    - [ ] 验证“退回公海”操作，确认负责人字段置空，状态变更。
    - [ ] 验证从公海“领取”客户，确认负责人更新为当前用户。
    - [ ] 验证公海客户对普通销售不可编辑/删除（除非领取）。
- [ ] **客户标签**:
    - [ ] 创建/管理客户标签。
    - [ ] 为客户打标签，验证支持多选及搜索筛选。

### 2.3 联系人管理 (Contacts)
- [ ] **关联性**: 在客户下新建联系人，验证其 `customer_id` 关联正确。
- [ ] **主要联系人**:
    - [ ] 设置某联系人为“主要”，验证显示标识。
    - [ ] 验证一个客户只能有一个主要联系人（自动取消旧的）。
- [ ] **数据校验**: 验证手机号/邮箱格式。

### 2.4 商机管理 (Opportunities)
- [ ] **商机创建**:
    - [ ] 关联客户，填写预计金额。
    - [ ] 验证必须关联有效客户。
- [ ] **阶段推进**:
    - [ ] 更改商机阶段（如：需求确认 -> 赢单）。
    - [ ] 验证赢单概率（Probability）是否随阶段自动更新（如：赢单=100%, 输单=0%）。
    - [ ] 验证输单时必须填写“关闭原因”。
- [ ] **产品关联**:
    - [ ] 在商机中添加产品，验证总金额是否自动计算（单价*数量*折扣）。
    - [ ] 修改产品数量，验证商机总金额联动更新。

### 2.5 产品管理 (Products)
- [ ] **产品维护**: 创建、上下架产品。
- [ ] **价格管理**: 修改产品价格，验证对新商机的影响（不应影响旧商机）。
- [ ] **状态控制**: 验证停用的产品在商机选择列表中不可见。

### 2.6 合同管理 (Contracts)
- [ ] **商机转合同**:
    - [ ] 从赢单商机生成合同，验证信息回填完整性（客户、商机名称、总金额、产品明细）。
    - [ ] 验证合同金额默认等于商机金额，但允许修改。
- [ ] **合同编号**: 验证合同编号的唯一性校验。
- [ ] **状态管理**:
    - [ ] 提交审批 -> 审批通过 -> 执行中 -> 已完成。
    - [ ] 验证状态流转的前置条件（如：未审核通过不可标记为执行中）。
- [ ] **文件上传**: 上传合同附件，验证下载/预览。

### 2.7 回款管理 (Payments)
- [ ] **回款计划**:
    - [ ] 针对合同创建分期回款计划。
    - [ ] 验证计划总金额等于合同金额（校验提示）。
    - [ ] 验证计划日期必须在合同有效期内（可选规则）。
- [ ] **回款记录**:
    - [ ] 录入实际回款，验证关联到对应计划。
    - [ ] **状态联动**:
        - [ ] 当实际回款 < 计划金额，计划状态为“部分回款”。
        - [ ] 当实际回款 >= 计划金额，计划状态为“已回款”。
    - [ ] 验证合同的总回款进度更新。

### 2.8 L2C 端到端全流程 (E2E Scenario) [Critical]
> 模拟真实销售场景，贯穿整个业务链条。

1. **线索接入**: 销售录入线索 "Acme Corp 咨询"，来源 "官网"。
2. **跟进转化**:
    - 添加一条 "电话沟通" 跟进记录。
    - 将线索转化为客户 "Acme Corp"，自动生成联系人 "John Doe"。
    - 验证：线索表状态=已转化，客户表/联系人表新增记录。
3. **商机挖掘**:
    - 为客户 "Acme Corp" 创建商机 "企业版订阅采购"。
    - 添加产品 "SaaS License" (数量10, 单价1000)，商机金额自动变为 10000。
    - 推进阶段至 "赢单"，填写概率 100%。
4. **合同签约**:
    - 基于商机生成合同，确认合同金额 10000。
    - 上传合同扫描件，状态变更为 "执行中"。
5. **回款执行**:
    - 创建两期回款计划（首款5000，尾款5000）。
    - 录入第一笔回款 5000。
    - 验证：第一期计划变 "已回款"，合同回款进度 50%。
    - 录入第二笔回款 5000。
    - 验证：合同状态自动变 "已完成"（若有此逻辑）或回款进度 100%。

## 3. 业务增强 (Enhancements) [P1]

### 3.1 跟进记录 (Activity)
- [ ] **记录跟进**:
    - [ ] 在线索/客户/商机下添加跟进记录（电话/拜访）。
    - [ ] 验证时间轴显示是否正确（倒序）。

### 3.2 仪表盘 (Dashboard)
- [ ] **可视化图表**:
    - [ ] **销售漏斗**: 验证各阶段商机数量/金额转化率显示。
    - [ ] **业绩趋势**: 验证按月/季度的回款或合同金额趋势图。
    - [ ] **核心指标**: 验证新增客户数、新增商机数等卡片数据准确性。
- [ ] **报表导出**: 将统计数据导出为 Excel。

### 3.3 AI 智能辅助 (AI Assistant) [P2]
- [ ] **对话助手**:
    - [ ] 呼出 AI 对话框。
    - [ ] **智能创建**: 通过自然语言指令创建线索或商机。
    - [ ] **自然语言查询**: 提问“上个月销售冠军是谁”等，验证返回结果。
- [ ] **智能查重**: 在录入客户/线索时，触发 AI 查重提示（相似度检测）。

## 4. 系统运维与架构 (Ops & Arch)
- [ ] **操作日志**:
    - [ ] 执行关键操作（如删除用户、修改合同）。
    - [ ] 在日志页面验证是否记录了操作人、时间、IP 和请求参数。
- [ ] **接口文档**: 访问 Swagger/Knife4j 页面，验证 API 文档可访问。
- [ ] **文件服务**: 验证通用文件上传接口（在合同/头像上传中使用）。

## 5. 数据库/数据完整性 (Data Model)
- [ ] **必填字段校验**: 验证数据库 `NOT NULL` 字段是否在 API 层拦截。
- [ ] **外键约束**: 尝试删除被引用的记录（如：删除有关联商机的客户），验证是否报错或提示。
- [ ] **索引效率**: (性能测试) 大数据量下查询客户/线索的响应时间。

## 5. 接口与 SQL 检查
- [ ] **SQL 注入**: 验证搜索接口是否存在注入风险（使用 `' OR '1'='1` 测试）。
- [ ] **事务一致性**: 验证线索转化等跨表操作，失败时是否回滚。
